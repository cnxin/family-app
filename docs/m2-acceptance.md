> 验收日期：2026-07-29
> 状态：通过，数据库核心边界冻结

## 验收结论

M2 已完成家庭数据边界、显式迁移、备份恢复、账号与成员拆分、可撤销会话、安全初始化、成员邀请、请求追踪和生产部署基线。后续日历、任务、观影、访客及连接器模块可以在同一核心模型上继续建设，不再为单个业务模块复制账号、家庭或权限体系。

## 冻结约定

1. `accounts` 是全局登录身份，只保存登录名、凭据状态和账号状态，不保存家庭角色。
2. 当前 `members` 表是家庭成员身份与展示档案。保留现有表名以避免重写业务外键；一个账号可通过不同成员身份加入多个家庭。
3. `members(householdId, accountId)` 唯一；未来允许不关联账号的儿童档案或占位成员，但不能借此绕过正式登录。
4. JWT 的 `sub` 等于 `accountId`，同时携带当前 `memberId`、`householdId`、家庭角色和服务端会话 ID。业务审计记录成员身份，账号只用于认证与跨家庭关联。
5. 所有家庭业务表和唯一约束必须包含 `householdId`。资源查询与修改必须同时校验 JWT 家庭范围，不能只凭资源 UUID。
6. 正式成员邀请只保存 Token 的 SHA-256 摘要、到期时间、目标角色和成员档案；明文只在创建时返回，领取、撤销或过期后不可复用。
7. 数据库只通过有序 TypeORM 迁移演进，`synchronize` 保持关闭。既有表名和外键采用渐进迁移，不因新增模块一次性重命名。
8. 全天计划使用 PostgreSQL `date`，具体时刻使用 `timestamptz`，家庭保存 IANA 时区；数量使用 `numeric` 并保存单位。
9. 生产环境的数据库、JWT 和首户初始化密钥通过文件挂载，不进入镜像、Git 或业务备份。
10. Web 当前使用 `localStorage` 保存会话，必须部署在 HTTPS 与严格 CSP 后；迁移到同站 `HttpOnly` Cookie 仍是外网强化项。

## 已知边界

- 由旧版无 PIN 成员迁移出的账号会保留无密码状态，以避免升级锁死。账号登录后会在“账号安全”明确提示补设密码；长期部署前必须完成。
- 当前登录支持通过家庭标识选择同一账号的多个家庭身份，但尚未提供完整的跨家庭切换器；在真实多家庭需求出现时补齐。
- 正式成员邀请与未来访客邀请是不同模型。访客不会创建为 `members`，也不会继承正式成员权限。
