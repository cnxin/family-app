# M3-C 通用家庭投票验收

> 验收日期：2026-07-29
> 状态：通过，家庭投票与透明结果契约冻结

## 验收结论

M3-C 已形成可供家庭决定、点菜、活动、观影和采购复用的投票闭环。成员可以在移动与桌面 Web 中发起单选或多选投票，设置可选截止时间，提交整组选择并随时改票或撤票；发起者和家庭管理员可以编辑、结束、重新开启或软删除投票。首页、独立投票页和通知中心均已接入。

## 数据约定

1. `polls` 保存家庭归属、标题、说明、分类、规则、截止时间、状态及可选来源引用，不保存日历副本。
2. `poll_options` 保存候选项和稳定排序。每个投票支持 2 至 12 个候选项，去除首尾空白后不允许重名。
3. `poll_votes` 保存成员对候选项的选择，并按投票、候选项和成员建立唯一约束。每次提交先删除该成员的旧选择，再写入完整新选择；空数组表示撤票。
4. 单选最多选择 1 项；多选最多选择数为 2 至候选项总数。服务端始终校验选项属于当前投票。
5. 截止时间到达或手动结束后禁止改票。重新开启要求截止时间为空或仍在未来。
6. 已有选票后不允许修改候选项、单选/多选模式或最多选择数，但标题、说明、分类和未来截止时间仍可维护。
7. 结果在家庭内透明展示候选项票数、参与成员比例及成员名单。结束后选票不可变，当前不创建 `poll_results` 快照，避免重复结果漂移。
8. `sourceModule` 与 `sourceId` 成对预留，供未来菜单、观影和采购等模块关联；当前普通创建接口不接受客户端指定来源。
9. 投票软删除后不再出现在列表，选票和候选项保留在家庭业务边界内。列表最多返回最近 50 条未归档投票。

## 权限约定

- 所有正式家庭成员均可发起和参与投票，也可查看同家庭的透明结果。
- 发起者或 `owner/admin` 可编辑、结束、重新开启和软删除投票。
- 普通成员不能管理他人发起的投票，但可在开放期间提交、修改或撤回自己的选择。
- 所有读取和写入同时按 `householdId` 与资源 ID 过滤；跨家庭访问按不存在处理。

## 通知约定

- 发起、结束和重新开启投票时通知同家庭的其他成员，不向操作人重复发送。
- 通知使用 `module=poll`，保存投票 ID 作为来源，并跳转到 `/polls?pollId=<id>`。
- 改票和撤票不产生通知，避免家庭成员在正常参与过程中收到高频消息。
- 截止或自定义时刻提醒由 M3-D 通用提醒引用投票 ID 实现，不向投票表写入提醒副本。

## 接口契约

| 接口 | 作用 |
| --- | --- |
| `GET /polls?status=open\|closed\|all` | 读取当前家庭的进行中、已结束或全部未归档投票 |
| `POST /polls` | 发起单选或多选投票 |
| `PATCH /polls/:id` | 发起者或家庭管理员编辑投票 |
| `POST /polls/:id/votes` | 用完整 `optionIds` 替换当前成员的选择，空数组撤票 |
| `POST /polls/:id/close` | 手动结束投票并通知其他成员 |
| `POST /polls/:id/reopen` | 在截止时间有效时重新开启投票 |
| `DELETE /polls/:id` | 软删除投票并从列表隐藏 |

## 后续边界

- 当前投票不直接进入日历；开放投票可以作为提醒来源，提醒通知跳回对应投票。
- 当前结果对家庭成员透明，不支持匿名投票、秘密投票、委托投票或发起后的新增候选项。
- 点菜、观影和采购后续通过来源关联创建投票，继续复用本模块的规则、权限、结果和通知能力。
