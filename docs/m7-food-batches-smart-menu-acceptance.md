# M7-A5.2 食品批次、保质期与智能菜单验收

> 验收日期：2026-08-06
> 实施分支：`uitest`
> 范围：食品批次、批次流水、FIFO 扣库预览、智能菜单提案、家庭投票采纳与普通成员首页精简

## 验收结论

库存数量继续由原有库存项和不可变库存流水管理，本批在其上增加可追溯食品批次。购物入库、菜单扣库、维护耗材扣库和撤销会在同一事务内同步批次数量与批次流水；没有批次的历史库存仍作为未分批数量参与库存校验，不会因迁移丢失或被自动拆分。

智能菜单是可解释提案，不是自动决策。系统按临期库存、现有食材、最近菜单和家庭做菜能力排序候选；用户必须先发起家庭投票、结束投票，再明确确认采纳，才会把获得选择的菜加入一周菜单。生成提案、投票和采纳均不会静默扣库，菜单完成后的库存扣减仍使用原有确认流程。

## 食品批次

- 同一库存项可登记多个批次，保存入库日期、生产日期、到期日期、开封日期、来源、创建成员和乐观锁版本。
- 批次列表显示正常、7 天内到期、已过期和未设置日期状态，并返回剩余天数、最早到期日、批次数量与未分批数量。
- 手工登记只能分配当前库存中尚未归入批次的数量，不会增加库存总量；同一幂等键重复提交返回原批次，复用于其他批次返回 `409`。
- 购物项确认入库时可同时填写批次日期，并建立 `shopping_item` 来源批次；并发重复确认只建立一份库存流水和一份采购批次。
- 日期更新要求提交 `expectedVersion`。旧版本、跨家庭访问、到期早于生产和超出库存数量均被拒绝。

## 批次流水与 FIFO

- 新增不可变 `inventory_batch_movements`，记录家庭、批次、库存流水、操作、变动前后数量、变化量、操作者快照、来源、幂等键、反向来源和时间。
- 类型包含分配、入库、消耗、调整和撤销；数据库触发器拒绝更新或删除历史批次流水。
- 菜单扣库预览按到期日期、生产日期、入库日期和创建顺序分配，未设置到期日期的批次排在最后；预览会明确显示各批次预计扣减和剩余未分批数量。
- 确认扣库使用事务行锁重新计算，不信任旧预览；库存不足、单位不匹配、并发变化或跨家庭访问均失败且不产生部分写入。
- 撤销原库存流水时建立反向批次流水并恢复批次数量，不删除原记录；同一批次流水最多撤销一次。

## 智能菜单

- `POST /smart-menu-plans` 最多生成 7 道一周晚餐候选，保存评分、推荐理由、临期食材快照、做法和建议日期。
- 提案必须至少有两道包含家庭默认做法的菜；开始日期不能在过去，也不能超过未来 60 天。
- 候选理由来自确定性家庭数据，包含临期食材、库存满足、家庭成员擅长和近期未重复，不调用 Hermes 或外部模型，不把智能体作为业务权威。
- `POST /smart-menu-plans/:id/poll` 建立多选家庭投票并保留候选映射；重复或并发发起只关联一个投票。
- `POST /smart-menu-plans/:id/adopt` 只接受已经结束且存在有效选择的投票。按票数、候选分数和原排序选取结果，避免同一菜单重复添加同名菜。
- 生成和采纳使用家庭范围幂等键、事务锁和唯一索引；幂等键复用于不同周次、重复采纳和并发确认不会产生重复菜单。

## 前端与交互

- 采购页使用“购物清单 / 家庭库存 / 智能菜单”三段导航，核心按钮和输入目标不小于 44px。
- 库存页展示批次汇总、临期与过期状态，并使用可下拉 `AdaptiveDialog` 登记日期和数量。
- 智能菜单展示每个候选的评分理由和临期食材，投票采纳前显示预计写入数量并要求明确确认。
- `AdaptiveDialog` 在手机和窄屏 Web 支持原生触控及标准 Web Pointer Event；鼠标或触控向下拖动会跟手移动并释放关闭，桌面宽屏仍使用居中弹窗。
- 普通成员首页默认只展示今日摘要、最多 3 项待处理事项和 4 个常用入口。本周概览、家庭动态、回忆和其他模块通过“更多家庭内容”点击展开；管理员首页保持原有信息密度。

## 安全边界

- 所有批次、提案、投票和菜单写入从 JWT 中取得家庭和成员身份，不接受客户端指定家庭。
- 自由名称购物项或未关联食材不会猜测库存；用户仍需先选择库存项或跳过。
- 本批不读取、修改或输出账号密码、Hermes 密钥、Plex Token 或 MoviePilot API Key。
- Hermes、Plex、Emby 和 MoviePilot 不参与批次或智能菜单事务，外部服务不可用不会影响库存闭环。
