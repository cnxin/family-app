# 独立菜谱与多人做法验收约定

> 验收日期：2026-07-29
>
> 状态：通过，菜品、做法、成员厨艺和菜单快照契约冻结

## 验收结论

菜谱已经从个人页内的菜品维护入口拆成独立家庭模块。同一道菜可以同时包含家庭默认做法和多个成员做法；任何正式家庭成员都可以查看全家做法，在自己下厨时直接切换参考默认做法、自己的做法或其他成员的做法。

## 数据约定

1. `dishes` 保存家庭共享菜品，不把菜品所有权绑定到单个成员。
2. `dish_recipe_variants` 保存做法版本；一个菜品最多有一个未归档的家庭默认做法，成员可各自保存做法。
3. 步骤、参考链接和食材分别保存在 `dish_recipe_variant_steps`、`dish_recipe_variant_links` 和 `dish_recipe_variant_ingredients`，并独立属于某个做法版本。
4. `member_dish_skills` 保存“谁会做什么菜”、`learning/can_cook/signature` 熟练度和该成员的常用做法。
5. 家庭成员可读取同一家庭的全部未归档做法。个人做法由作者或 `owner/admin` 维护；家庭默认做法仅 `owner/admin` 维护。
6. 新点菜默认选择家庭默认做法并写入 `menu_items.recipeSnapshot`；认领菜品时优先切换到认领人的常用做法，也可手动选择任意家庭可见做法。
7. 做法快照包含名称、作者、食材、步骤和参考链接。采购按快照计算，菜谱后续修改或个人做法归档不会改变既有菜单的采购依据。
8. 原有 `/dishes` 写接口继续维护家庭默认做法，旧客户端与新菜谱模块可以在迁移期并存。
9. 所有查询和写入同时校验 `householdId`；跨家庭资源按不存在处理。

## 接口契约

| 接口 | 作用 |
| --- | --- |
| `GET /recipes` | 查看家庭全部菜品、做法和成员厨艺关联 |
| `GET /recipes/:dishId` | 查看单道菜及全家所有可见做法 |
| `POST /dishes/:dishId/recipe-variants` | 新增自己的做法，管理员也可新增家庭默认做法 |
| `PATCH /recipe-variants/:id` | 作者或管理员编辑允许维护的做法 |
| `DELETE /recipe-variants/:id` | 归档个人做法；家庭默认做法不可归档 |
| `POST /member-dish-skills` | 标记会做、熟练度和自己的常用做法 |
| `DELETE /members/:memberId/dish-skills/:dishId` | 删除成员厨艺关联 |
| `PATCH /menu-items/:id` | 认领、更新状态或切换菜单采用的做法 |

## 前端约定

- 菜谱是独立一级入口，支持“按菜品”和“按成员”浏览及全文搜索。
- 菜品详情用紧凑切换控件展示家庭默认、自己和其他成员做法，不隐藏其他成员的内容。
- 成员可以标记“我会做”、设置熟练度和常用做法，并在独立编辑器维护图文步骤、食材与参考链接。
- 菜单中展示当前采用的做法，认领后仍可打开选择器切换；已经保存的菜单使用快照展示和采购。

## 后续边界

- 当前使用编辑更新与菜单不可变快照，不提供菜谱修订历史或两版差异比较。
- 图片仍使用现有上传存储；引入对象存储后需要为步骤图片增加引用计数和清理策略。
- 家庭默认做法用于没有个人偏好的稳定兜底，不代表其他成员做法不可被全家参考或选入菜单。
