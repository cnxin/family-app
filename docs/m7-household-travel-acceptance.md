# M7-A2 家庭出行计划与打包清单验收

## 交付范围

家庭出行模块保存行程名称、城市或区域、起止日期和普通备注，并提供成员协作清单与可复用打包模板。页面支持行程创建、编辑、完成、重开、取消、归档和恢复，也支持清单分工、完成、恢复、跳过、移除和模板应用，所有核心操作均可通过鼠标或触控完成。

本批不保存证件号码、票据内容、精确轨迹、支付信息或健康资料。普通备注和清单备注不会复制到家庭活动审计，服务日志也不记录这些正文内容。

## 数据与权限

- `travel_plans` 保存家庭行程、日期、状态、版本、创建者、更新者和完成信息。
- `travel_checklist_items` 保存清单分类、数量、排序、成员分工、状态、版本和模板来源。
- `travel_packing_templates` 与 `travel_packing_template_items` 保存家庭可复用模板和有序条目。
- `travel_template_applications` 唯一约束保证同一个模板在同一行程最多应用一次，并保存应用时的模板版本。
- `travel_operations` 保存家庭、操作、目标、行程、操作者、幂等键、请求指纹、非敏感结果摘要和时间；数据库触发器拒绝更新或删除历史行。
- 所有活动家庭成员可创建行程、模板和协作清单；行程创建者或 `owner/admin` 管理行程状态、移除条目和应用模板；模板创建者或 `owner/admin` 维护模板。
- 所有查询和写入都限制 `householdId`，跨家庭访问统一返回 `404`。

## 状态与一致性

行程状态为计划中、已完成或已取消，并可独立归档。完成前必须没有待处理清单项，成员需要明确完成或跳过每一项；完成、取消和归档会取消尚未发送的关联提醒，重开不会自动恢复提醒。

清单状态为待处理、已完成或已跳过。已完成项记录完成人和时间；恢复会回到待处理；移除使用归档时间保留历史。已完成、已取消或已归档行程不能继续静默修改清单。

所有写操作使用家庭级幂等键和 SHA-256 请求指纹。相同键和相同载荷重试返回原结果，相同键复用于不同载荷返回 `409`。行程、清单项和模板更新均提交 `expectedVersion`，事务行锁确保并发请求不会覆盖较新的成员操作。

## API

| 接口 | 行为 |
| --- | --- |
| `GET /travel-plans`、`GET /travel-plans/:id` | 按状态读取家庭行程及准备进度、清单和模板应用状态 |
| `POST /travel-plans`、`PATCH /travel-plans/:id` | 幂等创建或使用预期版本编辑行程 |
| `POST /travel-plans/:id/complete`、`reopen`、`cancel`、`archive`、`restore` | 使用预期版本执行明确的行程状态操作 |
| `POST /travel-plans/:planId/items` | 幂等增加分类、数量、备注和成员分工清单项 |
| `PATCH /travel-plans/:planId/items/:itemId` | 使用预期版本编辑清单项 |
| `POST /travel-plans/:planId/items/:itemId/complete`、`restore`、`skip`、`archive` | 显式完成、恢复、跳过或移除清单项 |
| `GET /travel-templates`、`POST /travel-templates`、`PATCH /travel-templates/:id` | 读取、创建和编辑家庭打包模板 |
| `POST /travel-templates/:id/archive`、`restore` | 使用预期版本归档或恢复模板 |
| `POST /travel-plans/:planId/templates/:templateId/apply` | 校验行程和模板版本后一次性应用模板 |

## 前端与聚合

- 首页增加独立“家庭出行”模块，桌面侧栏增加固定入口，移动底栏保持原有高频入口数量。
- 出行页提供行程/模板分段，以及计划中、已完成、已取消和已归档筛选。
- 行程详情显示日期、目的地、准备进度、分类清单和成员分工；数量使用步进器，状态操作使用可点击按钮和明确确认框。
- 模板应用前显示将增加的条目和数量，已经应用的模板显示明确状态并禁用重复操作。
- 出行计划聚合到统一日历，并可从出行页或日历进入提醒设置；提醒中心支持出行来源。
- 创建、模板应用和行程状态变化进入家庭活动流，审计只保存必要摘要和对象标识。
