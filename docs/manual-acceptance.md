# 小管家 · 人工验收清单

这份清单不是给机器跑的，是给**人照着用一遍**的。

自动化那边现在有 731 个 API 黑盒断言 + 69 个浏览器用例，它们证明的是「没坏」，
不是「好用」，而且有几类东西结构上就盖不到：

| 自动化盖不到的 | 原因 |
| --- | --- |
| 媒体外部连接器（Plex / Emby / MoviePilot / TMDB / 豆瓣 / Bangumi） | 测试环境全是空配置，只验证了「未配置」分支，真实 API 的返回形状从没见过 |
| 小管家接真实 Hermes | 测试里跑的是 `FakeAgentRuntime` 确定性桩 |
| 通知真实送达（ntfy / Webhook） | 测试里是 stub，没真的推送过 |
| 备份与恢复演练 | 只验证了状态机，没真的恢复过一次库 |
| 上传、图片、签名链接 | 只验证了响应形状，没验证过真实文件和浏览器行为 |
| 好不好用 | 没有任何自动化能回答 |

带 ★ 的条目就是上面这些盲区，**时间不够时优先跑带 ★ 的**。

## 怎么用

- **在哪跑**：真实部署（`docker-compose.prod.yml`，见 `docs/production-deployment.md`），连真的 Plex / MoviePilot / ntfy，用真实家庭数据。不要在开发库上跑。
- **谁跑**：至少两个人，一个管理员（爸爸）一个普通成员（妈妈）。有些条目专门验权限边界，一个人跑不出来。
- **跑多久**：核心场景一次性跑完约 60～90 分钟；带 ★ 的部分建议连续观察一周（备份、对账、通知重试都是按天跑的）。
- **怎么记**：每条勾 ✅ 或 ❌。**❌ 时请记下页面右下角/响应里的 `requestId`**——API 每个响应都带，有它我能直接定位到那一条请求日志，比截图有用得多。
- **设备**：手机浏览器和电脑各跑一遍首页 + 一个写操作。两套布局是分开实现的（`mobile-chrome` / `desktop-chrome` 两个 project），只在电脑上点等于只测了一半。

## 场景一 · 早上：今天有什么事

- [ ] 打开首页，今天的任务、日历事项、提醒、待办通知都在，数字和实际一致
- [ ] 手机窄屏下首页不横向滚动，关键按钮能用拇指点到
- [ ] 点一个任务 → 标记完成 → 积分有没有按设置加上
- [ ] 完成后再点「恢复」，积分退回，流水里能看到一正一负两条
- [ ] 日历切到下周，周期任务按规则展开（每日 / 每周 / 每月各看一个）
- [ ] 建一条提醒挂在某个日历事项上，到点收到通知
- [ ] 普通成员看不到管理员才有的操作入口（编辑别人的任务、改家庭设置）
- [ ] ★ 通知中心里的未读数，和手机上真实收到的推送条数对得上

## 场景二 · 中午：点菜到上桌

- [ ] 菜谱页新增一道菜，填食材和做法，保存后详情页显示完整
- [ ] 同一道菜加第二个「做法版本」，两个版本都能单独查看
- [ ] 点菜页给今天点 3 道菜，厨房页能看到这 3 道
- [ ] 厨房页逐道划掉，点菜的人收到「已划掉」通知
- [ ] 智能菜单：生成一次推荐，看推荐理由是否合理（不是报错就算过，合不合口味另说）
- [ ] 菜做完扣库存，食材批次按先进先出扣，剩余量对得上
- [ ] 撤销一次扣库，批次余量恢复原样

## 场景三 · 采购与库存

- [ ] 从菜单生成购物清单，缺的食材都在，已有的没被重复列
- [ ] 手动加一条清单项，勾选完成
- [ ] 采购回来录入实收数量，和计划数量不一致时差额显示正确
- [ ] 库存页盘点一次，调整数量后流水里有记录且不可篡改
- [ ] 重复提交同一次采购（刷新后再点一次），不会产生两条流水 —— 幂等键生效

## 场景四 · 记账

- [ ] 记一笔支出，选账户和分类，余额变化正确
- [ ] 新建一个账户和一个分类，立刻能在记账页选到
- [ ] 冲销一笔已记录的交易，余额回到冲销前
- [ ] 按月查看汇总，分类占比和明细加总一致
- [ ] 普通成员只能看到允许看的部分（按你们的设置确认）

## 场景五 · 晚上：看片 ★ 重点盲区

这一段是自动化完全没覆盖的，**请慢慢跑**。

- [ ] ★ 媒体设置页填入真实 Plex 地址和 Token，保存后状态显示「已连接」
- [ ] ★ 同上，填 MoviePilot 的 API Key，健康检查通过
- [ ] ★ Emby 如果有部署也接一下；没有就记一句「未部署」
- [ ] ★ 媒体库同步一次，片子数量和 Plex 里实际数量对得上
- [ ] ★ 搜索一部片（中文名和英文名各试一次），TMDB / 豆瓣 / Bangumi 三个源都返回结果，海报能显示出来
- [ ] ★ 海报图片在手机和电脑上都能加载（签名链接 + 图片代理这条路）
- [ ] ★ 加入「想看」，MoviePilot 那边产生订阅
- [ ] ★ 发起一次观影投票，家人投票，结果统计正确
- [ ] ★ 在 Plex 里真的播一集，观看记录页出现这条（webhook 走通）
- [ ] ★ 播到一半停掉，进度百分比更新正确
- [ ] ★ 断开 Plex（改成错误地址），页面显示「离线」而不是白屏或报错弹窗
- [ ] ★ 恢复地址，状态自动回到「已连接」

## 场景六 · 周末：来客人了

- [ ] 新建一次访客来访，生成访客链接
- [ ] ★ 用**没登录的浏览器**（或手机隐身窗口）打开访客链接，能看到该看的、看不到家庭隐私数据
- [ ] ★ 访客页的 Wi-Fi 二维码能被手机相机扫出来并连上
- [ ] 访客点一次菜，家里人在点菜页看得到这条请求
- [ ] 访客参与一次观影投票
- [ ] 来访结束后归档，访客链接失效（再打开应该是失效提示而不是报错）
- [ ] 归档后访客的个人信息按脱敏规则处理（姓名等按 `docs/m5-guest-anonymization-acceptance.md` 的约定）

## 场景七 · 家里的东西

- [ ] 资产页登记一件家电，填保修期
- [ ] ★ 上传一份保修单 PDF 或照片，**关掉页面重新打开，还能下载并正常打开**（签名链接这条路）
- [ ] 给这件资产建一条维护计划，到期后在首页/提醒里出现
- [ ] 维护时消耗一件耗材，库存扣减正确；撤销后恢复
- [ ] 知识库写一篇文章，改两次，版本历史里三个版本都在，能对比
- [ ] 知识库在**中等宽度窗口**（把浏览器拖到一半宽）下工具栏不溢出
- [ ] ★ 回忆页上传几张照片，缩略图和原图都能看，删掉一张后确实没了
- [ ] 出行页建一次行程，加行程项，日历里能看到

## 场景八 · 小管家 ★ 重点盲区

- [ ] ★ 助理设置里切到真实 Hermes 运行时，状态显示「Hermes 已连接」
- [ ] ★ 问「这周还有哪些家庭任务」，回答内容和任务页实际数据一致（**不只是有回答，要核对数字**）
- [ ] ★ 问一个需要跨域的问题，比如「冰箱里还有什么快过期」
- [ ] ★ 让它创建一个任务 → 出现提案卡片 → 点「确认执行」→ 任务页真的多了这条
- [ ] ★ 同样的提案点「放弃」，什么都不应该发生
- [ ] ★ 在菜品详情页点进小管家，页面上下文带过去了（它知道你在问哪道菜）
- [ ] ★ 新建对话后立刻打字，**字不会被清掉、发送按钮能亮**（这是 2026-09-16 刚修的 bug，请专门验一次）
- [ ] ★ 断开 Hermes，页面回到「离线模式可用」，本地摘要仍能回答
- [ ] 会话历史能翻、能归档

## 场景九 · 积分与奖励

- [ ] 管理员手工调整某人积分，流水正确
- [ ] 建一个奖励，成员兑换，积分扣除
- [ ] 管理员批准兑换；再建一个并拒绝，积分退回
- [ ] 积分不够时兑换被拒绝，提示清楚
- [ ] 同一次兑换重复提交不会扣两次

## 场景十 · 运维 ★ 重点盲区

- [ ] ★ 备份页手动触发一次完整备份，任务跑完状态是「成功」，产物大小不为 0
- [ ] ★ 跑一次恢复演练，结果显示校验通过（它只建临时库，不会碰生产库）
- [ ] ★ **真的从备份恢复一次到另一台机器或另一个库**，打开看数据完整——这一步最贵也最重要，一年至少做一次
- [ ] ★ 容量检查跑通，剩余空间数字和服务器 `df` 对得上
- [ ] ★ 配一个真实 ntfy 或 Webhook 渠道，触发一条通知，手机真的响了
- [ ] ★ 故意把渠道地址改错，观察重试与失败记录，然后改回来看能否自动恢复
- [ ] ★ 确认 `INTEGRATION_SECRET_KEY` 已经单独备份到数据库之外（数据库备份不包含它，丢了所有渠道凭据都解不开）

## 跨场景要盯的几件事

不用单独跑，但在上面任何一步里遇到都记下来：

- **重复点击**：任何「提交 / 保存 / 确认」按钮连点两下，不应该产生两条数据
- **两个人同时改**：两个人同时编辑同一条记录，后保存的那个应该有明确提示，不能静默覆盖
- **暗色模式**：切到暗色，文字对比度够、图标不消失
- **网络断一下**：手机切飞行模式再切回来，页面能恢复而不是卡在空白
- **过期链接**：任何带签名的下载链接，等超过有效期再点，应该是「已过期」而不是 500
- **中文和 emoji**：名称里带 emoji、特殊符号、超长文本，不应该把布局撑破或报错

## 发现问题怎么给我

一条就够：

```
场景X-第N条：做了什么 → 期望什么 → 实际什么
requestId: 0a3b0623-a86a-4870-8453-f7a30c775741   （如果是接口报错）
设备：iPhone Safari / Mac Chrome
```

有 `requestId` 我能直接定位到那一条结构化请求日志；没有的话截图也行，但会慢一些。

## 什么时候跑

1. **第一次：Phase 1 收口后（就是现在这批地基改完）。** 目的是确认这堆重构没动到任何实际功能。不用等 24 个域全换完——越早跑，出问题时排查范围越小。
2. **第二次：Phase 2 换栈决策门。** `polls` 和 `tasks` 跑在新栈上，真实使用两周无回滚才算过门。那是整个重构里唯一不可逆的决定，必须用真实使用数据来定。
3. **之后：Phase 3 每迁完一个域，跑对应场景那一节。**
