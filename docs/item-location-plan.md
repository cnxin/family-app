## 0. 现状与判断

- `inventory_items` 没有任何位置字段；`inventory_batches`（食材批次）也没有；`home_assets.location` 是 80 字符自由文本（`asset-detail.tsx` 显示「没记存放位置」）。三处各说各话，现在是零基础，加起来没有冲突。
- 扫地机地图是**栅格图**不是户型图：边缘锯齿、房间里有沙发/床/桌子的轮廓噪点、有灰色未清扫区、有 App 自己的 UI 叠层（「90°」「地图显示」按钮、机器人图标）。**直接当底图不能看，必须处理后再让人修正。** 但它给出的东西也正是我们要的：房间划分、房间名、相对位置和比例。
- 所以地图的定位是：**一次性导入 → 自动清理成房间多边形草稿 → 人在编辑器里改 → 在房间里画柜子。** 之后地图就是自家的数据，和扫地机再无关系。**不接任何扫地机 API**（Roborock / 石头 / 追觅的地图格式都是私有的，投入大、收益小）。

## 1. 已拍板 / 不做的事

| 已拍板 | 说明 |
| --- | --- |
| 位置是「上次放在」，不是真相 | UI 措辞用「上次放在 …」，错了就点一下改，不算数据错误，不做提醒、不做「位置待核实」之类的状态 |
| 一套位置字典，三处引用 | 库存物品、食材批次、家庭资产都引用 `storage_locations`；不再各自填文本 |
| 位置挂批次，物品只有默认值 | 同一样东西冷冻室一份、储物间一份是常态 |
| 地图是静态底图 + 人工修正 | 自动处理只是省力的辅助，**从第一天起就必须可以完全手画**（在原图上拖矩形），自动步骤失败不影响功能 |
| 地图数据自有 | 房间/柜子的形状存在自家数据库里，归一化坐标，和底图图片一起导出备份 |
| 录入只在入库时问一次「放哪儿」 | 默认带出该物品（其次该类别）上次的位置，多数情况直接确认 |
| 家人不负责维护 | 只有 King 建地图、建柜子；家人只做「入库选位置」「找不到就改位置」两个动作 |

| 不做 | 原因 |
| --- | --- |
| 接扫地机 API / 实时地图 | 私有格式、无收益 |
| 3D、多楼层、比例尺、真实尺寸 | 只要相对位置 |
| 位置变更历史/审计 | 「上次放在」语义下没意义；`inventory_batch_movements` 已有出入库记录够用 |
| OCR 房间名 | 房间就十来个，用户改名比识别可靠 |
| 逐格/逐层强制录入 | 三级（房间 → 柜子/区域 → 层/格）到顶，第三级可选 |
| 访客可见 | 位置只对家庭成员 |

## 2. 数据模型

新迁移一份（编号顺延），全部带 `householdId`、家庭隔离测试照旧补。

### 2.1 `storage_locations` 位置字典

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | uuid | |
| householdId | uuid FK | |
| parentId | uuid FK 自身，可空 | 空 = 房间 |
| kind | `room` / `zone` / `container` / `slot` | 房间 / 房间内区域（阳台角落）/ 柜子箱子冰箱 / 层格抽屉。约束：room 无 parent；slot 的 parent 必须是 container；深度 ≤ 3 |
| name | varchar(40) | 同一 parent 下唯一（`UQ (householdId, parentId, name)`，parent 为空时用表达式索引） |
| icon | varchar(40) 可空 | 复用 assets 的图标集 |
| sortOrder | int | |
| mapShape | jsonb 可空 | 见 §2.2；只有 room / zone / container 才有 |
| note | text 可空 | 「钥匙在门后挂钩」这类一句话 |
| archivedAt | timestamp 可空 | 软删；有物品引用时只能归档不能删 |

路径显示统一用 `房间 / 柜子 / 层`，服务端提供 `pathLabel`，客户端不自己拼。

### 2.2 `household_maps` 地图

一个家庭一张（表结构留 `isActive`，将来多张不改表）。

| 列 | 说明 |
| --- | --- |
| id, householdId | |
| title | 默认「家」 |
| backgroundUploadId | FK `uploads`，可空；处理后的底图（PNG，已裁掉扫地机 UI 叠层） |
| sourceUploadId | FK `uploads`，可空；原始截图，留着方便重做 |
| viewBox | `{ w, h }`，固定 `1000 × round(1000 * 原图高/宽)`，所有 shape 坐标都在这个坐标系里，**图片换了坐标不变** |
| updatedAt | |

`mapShape` 结构：`{ type: 'polygon', points: [[x,y],…] } | { type: 'rect', x, y, w, h, rotation? }`。房间用 polygon，柜子用 rect。坐标整数。

### 2.3 三处引用

- `inventory_items.defaultLocationId` uuid FK 可空。
- `inventory_batches.locationId` uuid FK 可空；`inventory_batches.locationUpdatedAt`。新建批次时若未指定，取物品 `defaultLocationId`。
- `home_assets.locationId` uuid FK 可空；**原 `location` 文本列保留**作为旧值展示（有 `locationId` 时不显示文本）。不做自动迁移：资产详情里旧文本旁边给一个「整理到位置」按钮，点了打开选择器，选完清空文本。全家资产就几十件，手点比猜准。
- 契约：`packages/contracts/src/locations.ts` 新文件（location、map、shape 的 zod），inventory / assets 契约各加可空字段。`api-inventory.md` 补端点。

### 2.4 端点（模块 `apps/api/src/locations/`）

- `GET /locations` 树（含 pathLabel、每个节点的物品数）；`POST` / `PATCH /:id` / `POST /:id/archive`；`PATCH /:id/shape` 单独一条，编辑器高频调用。
- `GET /locations/:id/contents` 该位置及子位置下的物品、批次、资产（按类型分组）。
- `GET /locations/search?q=` 只搜位置名，给 ⌘K 用。
- `GET /map` / `PUT /map`（title、viewBox、背景）；`POST /map/background` 上传处理后的 PNG（走现有 `upload` 模块，限 2 MB）。
- `PATCH /inventory/batches/:id/location`、`PATCH /assets/:id/location` 一跳改位置（「找不到 → 改」用的就是这两条）。
- 写操作全部进 H2 的域映射表，域 key `locations`；库存/资产改位置同时发对应域。

### I1 · 位置字典 + 三处引用 ［M］

- **管理页** `/house/locations`（放「家里」启动台的「资产」旁，架上级别）：树形增改归档、拖动排序。没有地图也能用。

### I2 · 地图导入、清理与编辑器 ［L］

目标：King 上传扫地机截图，几分钟内得到一张干净的、可改的、能画柜子的家庭地图。**图像处理在浏览器里做**（Canvas + Web Worker），不给 API 加 sharp/OpenCV 依赖，用户当场看到结果、当场改。

**I2a · 导入向导** `pages/house-map-import.tsx`（分四步，每步可退回）

1. **裁剪**：拖一个框把 App 的按钮、图例、机器人图标裁掉。样图里右侧「90°」「地图显示」和左上角充电座图标都在裁掉范围。裁剪后的图就是 `sourceUpload`。
2. **识别房间**（Worker 里跑，样图 1200×1300 应在 1 秒内）：
   - 颜色量化：把像素聚到 ≤ 8 个色簇（k-means 或固定网格量化都行），把接近白/浅灰/深灰的簇标为「非房间」（墙、家具轮廓、未清扫区）。
   - 每个色簇生成掩膜 → 形态学闭运算（半径按图宽 1% 取）→ **填洞**：完全被同色包围的洞（沙发、床、桌子）填掉 → 连通域分离，同色不相邻的是不同房间（样图中阳台/玄关/储物间同为橙色）。
   - 面积 < 图面积 0.3% 的连通域丢弃（噪点）。
   - 每个连通域取外轮廓 → Douglas–Peucker 简化（容差图宽 0.8%）→ **直角化**：相邻边夹角在 90°±15° 内的吸附成直角，短于图宽 1.5% 的边合并。目标是每个房间 4～12 个顶点。
   - 输出：`polygon[]`，坐标归一化到 §2.2 的 viewBox。
   - 识别不到（纯手绘图、黑白图）就跳到第 4 步，图当底图，让人手画。**这一条必须先有。**
3. **命名**：逐个高亮房间，让用户输入名字（样图有 12 个：阳台、客卧、客厅、卧室、主卧卫生间、玄关、卫生间、餐厅、书房、储物间、厨房，加左侧灰色区）；给 10 个常用名做按钮。灰色未清扫区默认不生成房间，用户可在第 4 步手画。
4. **底图**：用识别出的多边形重新渲染一张干净底图（每个房间平涂淡色、1px 描边、房名居中），**不再用原始截图当底图**——这就是「处理一下」的含义。渲染成 PNG 存 `backgroundUpload`；矢量本身也存在 `mapShape` 里，底图只是为了手机上渲染便宜。

**I2b · 编辑器** `pages/house-map.tsx` + `components/map-canvas.tsx`（SVG，不引第三方画布库；总行数 ≤ 600，超了拆）

- 两种模式：**看**（默认，家人用）和 **编辑**（King 用，导航里只对管理员显示入口）。
- 编辑房间：拖顶点、双击边加顶点、拖整个房间、右键/长按删顶点；改名；两个房间合并（选中两个 → 合并）；一个房间拆成两个（画一条线）。
- 画柜子：在房间里拖一个矩形 → 弹名字 → 成为该房间的 `container`；可旋转 90°、可拖动、可缩放；矩形必须落在房间内（超出就裁）。层格（slot）不上图，在柜子详情里列。
- 所有改动走 `PATCH /locations/:id/shape`，防抖 500 ms，失败回滚并提示。
- 看模式：点房间 → 侧栏/底部抽屉列该房间的柜子和直接放在房间的东西；点柜子 → 列内容物（`/locations/:id/contents`）；搜索框输物品名 → 命中的柜子高亮。
- 手机：看模式必须好用（双指缩放、单指平移）；编辑模式在手机上只允许改名和拖柜子，顶点编辑提示「请在电脑上做」。
- 底图 PNG 在 viewBox 上按 `preserveAspectRatio="none"` 铺满，所以裁剪后图片比例改了也不会错位——viewBox 由裁剪后的图决定，之后不再变。

**I2c · 导出/备份**：`GET /map/export` 返回 `{ map, locations }` JSON + 底图；备份模块（`system`）把 `uploads` 里的地图文件纳入现有备份范围（确认一下现有备份是否已覆盖 uploads 目录，覆盖了就不用动）。

- 黑盒：`shape` 校验（polygon ≥ 3 点、坐标在 viewBox 内、rect 在父房间内）；导出内容完整。
- 单测：清理算法用样图跑一遍，断言识别出 ≥ 10 个房间、每个 ≤ 16 个顶点、总面积占裁剪图 60%～95%（`apps/web/src/lib/floorplan/__tests__`，样图从 `docs/ui-prototypes/` 复制到测试 fixtures）。
- e2e：上传样图 → 走完四步 → 地图页看到 ≥ 10 个房间 → 在客厅画一个「电视柜」→ 入库时选择器里能选到 客厅 / 电视柜。
- 提交：`feat(web): 家庭地图导入与房间识别`、`feat(web): 家庭地图编辑器与柜子`、`feat(api): 家庭地图端点与导出`。

## 4. UX 规矩（防止「维护很麻烦」）

- 任何界面显示位置都用「上次放在 …」；没有位置就不显示，不用「未设置」占位。
- 入库表单里「放哪儿」永远是可选项，不设必填。
- 改位置永远一跳：列表行内、详情页、地图上拖过去（I2 编辑模式下把物品拖到别的柜子）。
- 选择器最多三层，每一层都能立刻结束；没有柜子的房间直接结束。
- 位置字典由 King 维护；家人在选择器里「新建」只能建当前层级的一个叶子，且默认 `zone`，不会把树建乱。
- 地图编辑入口只对管理员显示；家人看到的是「看」模式。

## 5. 验收（在 Mac mini 演示栈上）

1. 入库一样东西，选「厨房 / 吊柜 / 左」，库存视图按位置分组能看到，⌘K 搜到并带路径。
2. 同一物品第二个批次放「储物间」，两条批次各自位置正确，物品默认位置不变。
3. 用样图走完导入向导，≥ 10 个房间被识别并命名，底图干净无按钮无机器人图标。
4. 在客厅画「电视柜」，入库时能选到；地图看模式点它列出刚入库的东西。
5. 资产详情旧文本「整理到位置」后文本消失、路径显示正确。
6. 手机上看模式缩放平移顺畅，点房间出抽屉。
7. 归档一个有物品的位置：被拒并提示先移走；移走后可归档；归档后选择器里不出现。
8. 跨家庭：另一家庭看不到位置、地图、内容物。
9. 备份还原后地图与底图都在。
