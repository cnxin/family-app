# M6-A4 积分与奖励验收

## 已交付

- 新增家庭通用积分账户和不可变积分流水，积分能力不限定儿童场景，也不依赖奖励目录启用。
- 家庭管理员可为成员发放或扣减积分；成员可查看全家余额、自己的积分变化和家庭公共流水。
- 新增家庭奖励目录，支持名称、说明、兑换积分、启用和停用；停用不会删除已有兑换历史。
- 成员申请兑换时立即扣除积分，避免多个并发申请超出余额；管理员随后确认或拒绝。
- 待确认兑换可由申请人取消；拒绝、取消和管理员撤销已确认兑换都通过反向流水退回积分。
- 任务可配置完成积分。只有 `owner/admin` 能设置积分，负责人完成任务时发放，恢复任务时反向冲销，再次完成使用新的流水版本。
- 积分、奖励和兑换操作进入家庭活动；兑换处理结果进入通知中心并跳回对应记录。
- 首页和桌面导航新增积分入口，积分工作台支持鼠标和触控完成积分调整、奖励维护、兑换、审批和撤销。

## API 与数据

```text
GET   /points/accounts
GET   /points/ledger
POST  /points/adjustments
POST  /points/ledger/:id/reverse
GET   /rewards
POST  /rewards
PATCH /rewards/:id
POST  /rewards/:id/redemptions
GET   /reward-redemptions
POST  /reward-redemptions/:id/decision
POST  /reward-redemptions/:id/cancel
POST  /reward-redemptions/:id/reverse
```

- `points_accounts` 按家庭和成员唯一保存余额缓存。任何变化都在事务中锁定账户行，余额不能小于 0。
- `points_ledger` 保存变动前、变化量、变动后、成员、操作者、来源、幂等键、反向流水引用和时间。数据库触发器拒绝任何 `UPDATE` 或 `DELETE`。
- `rewards` 保存家庭奖励主档；家庭内名称唯一，兑换积分必须为正整数。
- `reward_redemptions` 保存奖励名称和积分快照、申请人、扣分流水、处理人、退分流水及 `pending/approved/rejected/cancelled/reversed` 状态。
- 迁移 `1785229700000-add-points-and-rewards` 建立四张表，增加任务积分字段，并扩充活动和通知模块；`1785229800000-normalize-points-unique-indexes` 兼容规范化曾由热重载实例执行的首稿约束，不改变业务数据。当前仓库共 36 个有序迁移，`synchronize` 保持 `false`。

## 事务、幂等与并发

- 手工积分、兑换申请、审批、取消和撤销都接收幂等键；家庭和幂等键组合唯一。
- API 使用事务级 advisory lock 串行化同一来源键，再使用积分账户行锁保护余额；重复点击和接口重试返回同一结果，不重复改变余额。
- 不同幂等键的并发兑换仍会在账户行锁处串行执行，后到请求若余额不足返回 400。
- 同一幂等键用于不同成员、变化量、奖励或处理结果时返回 409，不复用旧结果。
- 兑换申请先扣分。确认通过不再次扣分；拒绝、取消或撤销只允许发生一次，并保存指向原扣分流水的唯一反向流水。
- 手工积分只能从积分流水页撤销；任务积分必须通过恢复任务撤销，兑换积分必须通过兑换状态操作撤销，避免原业务状态与余额不一致。

## 权限与家庭边界

- 所有积分账户、流水、奖励和兑换查询都按 `householdId` 隔离，其他家庭 ID 按不存在处理。
- 所有成员可查看家庭积分余额、公共流水和启用奖励，可申请兑换，并可取消自己的待确认兑换。
- 普通成员只能读取自己的兑换记录；`owner/admin` 可查看全家兑换并进行确认、拒绝和撤销。
- 只有 `owner/admin` 可调整积分、撤销手工流水、维护奖励目录和设置任务积分。
- 积分不足时拒绝扣分。若任务积分已被消费，恢复任务会因无法完成反向冲销而失败，保持任务状态和积分事实一致，管理员应先补足或纠正积分。

## 前端验收

- 首页展示本人积分，桌面侧边栏和移动端路由均可进入“积分奖励”。
- 顶部展示本人余额和全家余额；奖励、兑换和流水使用独立视图，状态可以直接扫描。
- 积分调整表单显示“变动前 + 变化量 = 变动后”；不允许提交 0、非整数或负余额结果。
- 兑换确认显示扣分前、成本和扣分后余额；拒绝、取消、撤销和手工流水撤销显示预计退分或扣分结果。
- 奖励新建、编辑、启停，兑换申请，审批、取消和撤销都提供可点击/触控按钮、加载状态、成功反馈和失败信息，不依赖快捷键。
- 任务表单仅向管理员显示完成积分；任务行显示预计积分与已发放状态。
- 通知中心和家庭活动为积分使用独立图标，通知可直接打开对应兑换。

## 自动验收

- 全新数据库初始化、旧结构升级和结构漂移检查覆盖四张新表、任务字段、检查约束和外键。
- API 回归验证普通成员越权、手工发放、负余额保护、重复幂等键载荷冲突和相同请求并发合并。
- 兑换回归验证申请时扣分、重复申请、余额不足、重复审批、冲突改判、拒绝退回、申请人取消和管理员撤销。
- 任务回归验证管理员配置权限、完成发放、重复完成、恢复冲销和再次完成的新版本流水。
- 随机其他家庭奖励验证兑换和修改均返回 404；成员兑换列表只包含本人记录。
- 数据库直接更新和删除积分流水均由不可变触发器拒绝；积分活动和处理通知均有断言。
- 全量 API 回归继续覆盖库存、资产、访客、媒体、提醒、家庭隔离、日志脱敏和登录限流。
- TypeScript、lint、Expo Web 导出和服务可用性作为交付门禁。

## 后续边界

本批不增加儿童档案、零花钱、真实货币或财务结算。积分仅是家庭内部协作计数，不能表示现金、债权或支付余额。奖励履约仍由家庭成员线下完成，后续如需库存礼品或限量次数，应另建显式库存和履约模型，不从名称推断。
