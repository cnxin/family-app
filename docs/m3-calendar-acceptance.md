# M3-A 统一日历验收与数据约定

> 验收日期：2026-07-29
> 状态：通过，统一日历展示契约冻结

## 验收结论

M3-A 已完成统一日历的首个可用闭环。家庭成员可以在移动和桌面 Web 中按月查看菜单及手动家庭事件，并完成事件的新建、编辑和删除。菜单仍由菜单模块保存，统一日历只在读取时聚合，因此后续任务、观影、访客和维护模块可以接入同一展示模型而不迁移或复制业务数据。M3-B 已按这份约定把家庭任务作为第三种来源接入，未向 `calendar_events` 写入任务副本。

## 数据约定

1. `calendar_events` 只保存成员手动创建的家庭事件，不保存菜单、任务、观影、来访或维护记录的副本。
2. 全天事件使用 `date`；可选的开始和结束时刻使用 `timestamptz`。结束时间必须晚于开始时间。
3. 每个事件必须保存 `householdId` 和 `createdById`。列表、修改和删除均同时校验 JWT 中的家庭范围。
4. 所有正式家庭成员都可创建事件；创建者可维护自己的事件，`owner/admin` 可维护家庭内全部事件。
5. 跨家庭资源按不存在处理并返回 `404`，避免泄露资源是否存在；家庭内无管理权限返回 `403`。
6. 菜单餐次只有存在非 `rejected` 菜品时才进入统一日历；菜品数来自实时聚合。
7. `GET /menu-dates` 继续保留，现有调用无需随 M3-A 迁移。
8. 家庭任务由 `household_tasks` 与 `household_task_instances` 保存；日历读取时按范围展开周期规则，并以 `module=task` 返回。

## 接口契约

| 接口 | 作用 |
| --- | --- |
| `GET /calendar?start=YYYY-MM-DD&end=YYYY-MM-DD` | 聚合指定范围内的菜单餐次、家庭任务和家庭事件，单次最多 371 天 |
| `POST /calendar-events` | 创建家庭事件 |
| `PATCH /calendar-events/:id` | 创建者或家庭管理员编辑事件 |
| `DELETE /calendar-events/:id` | 创建者或家庭管理员删除事件 |

统一条目包含 `id`、`sourceId`、`module`、`date`、`startsAt`、`endsAt`、`title`、`summary`、`status`、`targetPath` 和模块元数据。`sourceId` 指向来源业务表主键，`module` 决定前端展示和跳转方式。

## 后续边界

- M3-A 不包含提醒、周期事件、任务或投票；这些能力在后续批次使用独立业务表。
- 当前事件时间由客户端转换为绝对时刻。引入多时区家庭或跨时区出行前，需要补充按家庭时区解释本地时间的服务端契约。
- 后续来源接入统一日历时，只实现聚合适配和目标页面跳转，不向 `calendar_events` 写入镜像记录。
