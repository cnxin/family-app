# M4-F 多片候选投票验收

> 完成日期：2026-07-30  
> 实施范围：从家庭片单选择多部影视、结构化候选引用、状态协作、并发保护与双视口 Web 交互

## 1. 数据模型

- 继续复用通用的 `polls`、`poll_options` 和 `poll_votes`，不建立观影专用投票表。
- `poll_options.mediaId` 可选关联 `household_media.id`；普通投票仍保存文字候选，选片投票的每个选项保存真实片单引用。
- 候选标签同时保存为投票快照。已结束但尚未归档的投票仍保护候选，确保可以可靠重开；归档时解除媒体引用，历史投票继续保留当时的候选名称和选票。
- 同一投票内不能重复选择同一片单条目；普通文字候选与影视候选不能混用。
- 影视候选只允许用于 `movie` 分类，且不能同时设置投票级 `sourceModule/sourceId`。

## 2. 家庭与状态边界

- 创建时按当前 `householdId` 一次性读取全部候选，任一 ID 不属于当前家庭时整笔请求失败。
- 只有 `watchlist` 或 `voting` 状态可以进入候选；创建成功后所有候选同步为 `voting`。
- 结束或归档后，仅在候选没有其他活动投票时恢复为 `watchlist`；重新开启时再次校验全部候选。
- 单片来源投票和多片候选投票共享冲突检查，不能用另一种投票形式绕过限制。
- 活动投票中的候选不能修改为其他观影状态，也不能移出片单。
- 已结束但仍可重开的选片投票会阻止候选被移出；归档投票后解除引用，片单即可正常清理。

## 3. 并发与一致性

- 创建、重开、结束、归档、修改片单状态和移出片单均按家庭与媒体 ID 获取 PostgreSQL 事务级 advisory lock。
- 多个候选按 UUID 排序后依次加锁，避免请求以不同候选顺序进入时发生锁顺序反转。
- 共享任一候选的两个并发创建请求只允许一个成功；冲突请求返回 `409`。
- 服务端从本地 `media_titles` 生成候选标签并返回本地媒体快照，不信任客户端提交的影片名称，也不在读取投票时调用外部元数据源。

## 4. Web 交互

- 家庭片单提供“选片投票”入口，支持鼠标和触摸逐项选择，2 至 12 部后进入投票表单。
- 表单中可继续增减符合状态要求的候选，并设置标题、单选/多选规则和截止时间。
- 投票卡展示影片名称、类型、年份、海报回退和票数，每个候选都有独立的“查看片单”链接。
- 创建成功返回片单时自动退出候选选择模式，卡片显示“查看投票”操作。
- 已创建的结构化候选不可原地改成另一组影视；需要调整候选时重新发起，避免已有选票和片单状态失配。

## 5. 自动验证

- 数据库迁移和实体结构漂移检查通过。
- API 回归覆盖混合/重复/错误分类/非本家庭候选拒绝、媒体快照、状态保护、关闭、重开、归档和并发创建。
- 既有单片来源投票、通用投票、MoviePilot 请求、三源搜索和家庭隔离回归全部通过。
- Expo Lint、API 与移动端 TypeScript 检查通过。

## 6. 后续边界

本批不根据票数自动安排胜出影片。平票、无人投票和家庭临时改期都需要明确的人为决定。下一批观影工作仍是 MoviePilot 媒体就绪事件，以及 Plex/Emby 播放进度和观看记录。
