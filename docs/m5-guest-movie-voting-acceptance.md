# M5-C1 访客观影投票验收

## 已交付

- 家庭管理员在创建访客邀请时可显式开启“允许参与观影投票”；默认关闭。
- 获授权的有效邀请可读取本家庭仍开放、未归档且未截止的观影投票，并提交或修改自己的选择。
- 访客选票以独立记录保存，不创建家庭账号或成员身份；家庭投票结果会计入匿名访客票数，但不会返回访客资料或成员投票名单。
- 邀请撤销、到期、来访取消或投票关闭后，公开读取和写入立即失效。

## API

```text
POST /visits/:id/invitations                                      (allowsMovieVoting 可选，需 manage_guests)
GET  /guest-invitations/:token                                    (公开；capabilities.movieVoting 表示是否授权)
GET  /guest-invitations/:token/movie-polls                        (公开；仅限有效、已授权邀请)
POST /guest-invitations/:token/movie-polls/:pollId/votes          (公开；提交或修改访客选票)
GET  /polls/:id                                                   (家庭登录；结果合并匿名访客票)
```

公开投票响应仅包含候选影视、投票规则、当前访客选择和匿名统计，不包含家庭成员、选民列表、账户信息、访问令牌摘要或媒体连接器凭据。

## 自动验收

- 默认邀请不能读取或参与观影投票。
- 授权邀请只能读取开放中的 `movie` 类投票，不能读取其他家庭或其他类别投票。
- 访客可改票；同一邀请对同一候选项不会重复计票。
- 家庭投票详情的参与人数和票数会合并访客选票，但访客不会出现在 `voters` 或成员目录中。
- 邀请和来访失效后公开端点返回 404。

## 后续边界

- 撤销邀请不会删除已提交选票，历史统计保留；若产品需要撤回历史票，应作为显式管理操作另行设计。
- 访客点菜不复用菜单操作者或家庭成员投票模型，将在 M5-C2 以独立的“访客点菜请求”记录实现。
