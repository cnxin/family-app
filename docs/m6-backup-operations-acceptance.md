# M6-A7 备份运维验收

## 交付范围

家庭管理员可以查看 backup worker、存储容量、最近备份和运行历史；配置每天或每周备份、天数与份数双重保留、容量警告和严重阈值，以及每月恢复演练。手动备份、容量检查、恢复演练和取消排队任务都需要明确点击与确认，支持鼠标和触控。

系统采用控制面与执行面分离：NestJS API 负责家庭权限、幂等排队、计划和通知；独立 worker 直接连接 PostgreSQL，只读挂载上传卷并写入专用备份目录。API 容器和 worker 都不挂载 Docker socket，API 响应不返回文件路径、备份标签或备份内容。

## 数据与状态

- `backup_policies`：每个家庭唯一策略，保存本地时区下的计划、保留阈值、容量阈值、下一次运行时间和 worker 心跳。
- `backup_runs`：保存完整备份、恢复演练和容量检查的排队、运行、成功、失败或取消状态，以及操作者、来源备份、大小、校验、迁移数量、保留结果和脱敏错误。
- 家庭与幂等键联合唯一；同家庭同类活动任务只允许一个，worker 使用 `FOR UPDATE SKIP LOCKED` 原子领取。
- 运行超时由 API 标记失败；成功、失败和容量状态变化进入 `system` 通知，策略、排队和取消进入家庭活动审计。
- 运行历史不提供删除或任意修改接口。保留清理只删除受管文件并将历史标记为已清理。

## API

| 接口 | 行为 |
| --- | --- |
| `GET /system/backups` | 管理员读取脱敏策略、worker、容量和运行历史 |
| `PUT /system/backups/policy` | 保存计划、保留、容量和演练策略 |
| `POST /system/backups/runs` | 幂等加入完整备份队列 |
| `POST /system/backups/capacity-checks` | 幂等加入容量检查队列 |
| `POST /system/backups/runs/:id/restore-drills` | 使用本家庭已校验且仍保留的备份演练 |
| `PATCH /system/backups/runs/:id/cancel` | 只取消尚未领取的任务并保留历史 |

普通成员返回 `403`；不存在或跨家庭运行返回 `404`。策略限制小时、分钟、星期、保留范围和阈值顺序，恢复演练不能引用失败、已清理、未校验或其他家庭备份。

## 执行与恢复边界

每份完整备份包含 PostgreSQL 自定义格式转储、上传文件归档、非敏感清单和 SHA-256 校验和。目录由家庭 UUID 与运行 UUID 两层组成，worker 在创建、读取和清理前都验证格式。`.incomplete` 标记保证未完成目录不会参与恢复。

恢复演练只创建 `family_restore_<随机运行 ID>` 临时数据库，校验归档路径，执行当前有序迁移并解压附件到临时目录。成功或失败都会清理临时数据库和临时附件，不覆盖 `family_app` 或活动上传卷。`restore-prod.sh` 同样拒绝活动生产数据库，但保留新恢复库与附件预览供人工核对。
