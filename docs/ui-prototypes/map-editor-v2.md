## 0. 现在的问题与一句话方案

- **地方不够**：编辑时标题、左树、工具条、底部导航都还在，地图只剩中间一块；手机上更挤。
- **面板占地方**：选中之后工具条和改名输入框加在地图上方一整行，画布跟着变矮、跳一下（I2 为此修过两次）。
- **改形状费劲**：拖顶点全靠手对，没有吸附；把一块修成方的、和隔壁墙对齐都得一个个点拖；删顶点要右键（手机和触控板都难用）。
- **拆不开**：识别把「主卧卫生间」并进了「卧室」，编辑器里没有拆分，只能删了重画。
- **只有柜子一种东西**：床、沙发、马桶这些认方位用的东西画不上去；柜子只能拖矩形，没有图标，看不出是什么。

**方案**：进编辑就进**全屏沉浸编辑**——地图铺满视口，只留一条工具栏、一个「完成」、一个收起的房间抽屉；
选中什么就在它**旁边**冒出一个小工具条（像 Figma），不再加整行面板；
拖顶点**自动吸**墙和直角，加「矩形化」「对齐相邻」「拆分」「合并」；
加一个**家具库**：收纳类（进位置树、能放东西）和装饰类（只画），每种一个顶视图图标。

## 1. 编辑器布局

### 1.1 全屏沉浸

- 在地图页点「编辑」（只管理员看得到）→ 编辑器用 portal 盖在整个应用之上（`fixed inset-0`，层级高于侧栏、底部导航和顶栏），
  隐藏页面标题、左树、底部导航；地图铺满视口，进来时**自动缩放到全图适配**（视口的 `reset()`）。
- 右上角只留 **「完成」**，旁边一行小字保存状态：`保存中…` / `已保存` / `没保存上 · 重试`。
- 点「完成」：先把防抖里没发出去的改动立刻发掉（`useShapeSaver.flush()`），发完再退出；退出恢复原页面、原来的缩放位置不保留（回到看模式的全图）。
- 手机返回手势 / 浏览器后退：进编辑时压一条 history（`?edit=1`），后退就等于点「完成」，不会直接离开地图页丢改动。
- 锁住 body 滚动；键盘 `Esc` 先取消选中，没选中时不退出（防手滑），退出只认「完成」和后退。

### 1.2 工具栏（固定一条）

| | 桌面 | 手机 |
| --- | --- | --- |
| 位置 | 顶部居中浮动胶囊（毛玻璃） | 底部固定一条（拇指够得着，让开安全区） |
| 按钮 | 选择 · 画房间 · 家具库 · ｜ · 撤销 · 重做 | 选择 · 家具 · 撤销 · 重做（画房间见 §6 待定） |

- 「家具库」在桌面上打开**左侧浮动面板**（不遮中间），在手机上打开**底部 sheet**（复用 `DetentSheet`，非模态，半开档）。
- 撤销 / 重做不可用时置灰；桌面快捷键 `⌘Z` / `⇧⌘Z`（Windows `Ctrl`）。

### 1.3 浮动小工具条（选中后出现）

- **内容**：
  - 房间：改名 · 删除 · 更多
  - 柜子 / 家具：改名 · 转 90° · 删除 · 更多
  - 选中了一个顶点：删这个点 · 取消
- **「更多」弹层**：
  - 房间：矩形化 · 对齐相邻 · 拆分 · 合并到… · 从图上拿掉
  - 柜子：吸附墙边（开 / 关）· 换成别的家具… · 挪到别的房间… · 从图上拿掉
- **位置规则**（不能遮住对象本身）：
  1. 按对象在屏幕上的外接框算，默认放在**上方** 10px、水平居中。
  2. 上方放不下（离屏幕顶 < 工具条高 + 顶部留白）就放**下方**。
  3. 对象比屏幕还高时贴在可见部分的顶上。
  4. 左右夹在屏幕内 8px。
- 「更多」弹层挂在工具条同一侧，优先放在对象外侧（右边 / 左边），放不下才叠在工具条下方；同样不压对象。
- 拖动、捏合、平移时工具条**先隐藏**，松手后在新位置淡入（ease-out 150ms，从对象方向微缩放 0.96→1）；`prefers-reduced-motion` 时直接出现。
- 改名：点「改名」在工具条原地变成输入框（宽度 ≤ 220px），回车保存、`Esc` 取消；不再往地图上方加整行。

### 1.4 房间抽屉

- 左上角一个小胶囊「☰ 房间 11 ▸」，**默认收起**；展开是一个窄列表（名字 + 柜子数），点一项 = 选中并对准那间房。
- 展开 / 收起记在本机（localStorage，读写包 try/catch），只是个方便。
- 左树（位置清单）在编辑态整体隐藏；要改树结构（层格、区域、归档）照旧在看模式的左树 / 手机「清单」里做。

## 2. 改形状省力

### 2.1 吸附

拖顶点、拖房间、拖柜子时实时吸附，吸住时画一条**橙色虚线参考线**，松手消失。桌面按住 `⌥`（Alt）临时不吸。

| 拖什么 | 吸到哪 | 阈值 |
| --- | --- | --- |
| 房间顶点 | 相邻房间的边（投影到最近的边上）、相邻房间的顶点 | 屏幕 8px |
| 房间顶点 | 直角：和前后两个顶点连成的边接近水平 / 竖直（±7°）时吸成水平 / 竖直 | ±7° |
| 柜子 / 家具 | 所在房间的墙（外接框的四条边）、同房间其他柜子的边 | 屏幕 8px |
| 整间房 | 相邻房间的边（整体平移对齐） | 屏幕 8px |

算法放 `packages/shared/src/map-geometry.ts`（纯函数，单测覆盖），画布只负责显示参考线。

### 2.2 一键操作（在「更多」里）

- **矩形化**：用外接矩形替换多边形（4 个顶点）。里面的柜子都还在外接框内，不动。
- **对齐相邻**：
  - 对选中房间的每条边，找相邻房间里**近乎平行**（±7°）、**距离 ≤ 12 单位**、**投影有重叠**的边，把选中房间这条边挪到那条边上。
  - 只动选中的这间，不动邻居；一次对齐所有符合条件的边，结果进撤销栈。
- **删顶点**：点一个顶点 → 它变实心、出现浮动条「删这个点」；按 `Delete` / `Backspace` 或点按钮删除。至少留 3 个顶点。右键删仍保留给习惯的人。

### 2.3 拆分（编辑器）

1. 选中房间 →「更多 → 拆分」→ 进入画线状态，提示「从墙到墙画一条线」。
   - 桌面点两下（起点、终点）或拖一下；手机不开放（见 §6）。
   - 线的端点吸附墙边和直角；画的时候实时预览两块的颜色。
2. 线必须和房间边界**正好交两次**，否则提示「线要从一面墙画到另一面墙」、不生效。
3. 切出两块：大的一块保留原房间（原名、原 id）；小的一块弹出起名（常用名 + 「主卧卫生间」这类建议），成为**新房间**。
4. 原房间里的柜子 / 区域，按中心点落在哪块就归哪块（服务端一并改上级）；直接记在原房间上的东西留在原房间，在确认框里写明。
5. 走新端点 `POST /locations/:id/split`，一个事务完成：改原形状、建新房间、挪子位置。

### 2.4 合并（编辑器）

1. 选中房间 →「更多 → 合并到…」→ 相邻房间高亮成可点，点一个作为目标；弹确认框。
2. 形状用导入步骤已有的 `mergeRooms`（栅格化并集 → 描边 → 简化 → 直角化）。
3. 走新端点 `POST /locations/:id/merge { intoId, shape }`，一个事务完成：
   - 被并房间下的柜子 / 区域挪到目标下，重名加「 2」；
   - 记在被并房间上的库存物品、批次、资产改记到目标；
   - 被并房间归档；
   - 目标换成合并后的形状。

## 3. 家具库

### 3.1 两类

| | 收纳类（10 种） | 装饰类（8 种） |
| --- | --- | --- |
| 种类 | 衣柜、鞋柜、电视柜、吊柜、地柜、冰箱、书柜、床头柜、储物架、抽屉柜 | 沙发、床、餐桌、书桌、马桶、浴缸、洗衣机、灶台 |
| 存哪 | **位置**：`storage_locations` 里一个 `container`，`icon` 存家具类型键（列已有，varchar 40），形状照旧存 `mapShape` | **只画**：`household_maps.decorations`（新 jsonb 列），不进位置树 |
| 进树 / 能放东西 | 是：入库选择器里选得到，看模式可点、列内容物 | 否 |
| 看模式 | 实线框 + 图标 + 名字，可点 | 虚线淡色框 + 图标，不可点（`pointer-events: none`） |
| 名字 | 自动「衣柜」「衣柜 2」…（同一房间里不重名，沿用唯一索引），可改 | 不起名，只显示类型 |

- 现有「拖矩形画柜子」保留，改名为「**自定义柜子**」，放在家具库面板底部；画出来的是没有 `icon` 的收纳类。
- 现有柜子（I2 画的）都是 `icon = null`，看起来就是自定义柜子，不用迁移。

### 3.2 放置与调整

- 家具库里点一个 → 落到**当前选中房间**的中央；没选中房间就落到屏幕中心所在的房间；都没有就提示「先点一个房间」。
- **默认尺寸**：地图没有比例尺，按「viewBox 1 单位 ≈ 1 厘米」估（样图卧室约 377 单位宽，对应常见 3.6～4 米）。
  - 收纳：衣柜 160×60、鞋柜 100×35、电视柜 180×40、吊柜 120×35、地柜 120×60、冰箱 70×70、书柜 120×35、床头柜 45×45、储物架 100×45、抽屉柜 80×45
  - 装饰：沙发 200×85、床 180×200、餐桌 140×80、书桌 120×60、马桶 40×65、浴缸 150×75、洗衣机 60×60、灶台 75×45
  - 放不下（超过房间短边的 60%）就等比缩到 60%。
- **调整**：
  - 拖动挪位置（夹在房间内，吸墙）；
  - 四角都能拉大小（现在只有左上、右下两个角）；
  - 转 90°：宽高互换，同时记朝向，图标跟着转；
  - 换房间：拖出房间外松手不生效，改用「更多 → 挪到别的房间…」。
- 放下、删除、换房间时手机轻振一下（`navigator.vibrate`，没有就算了）。

### 3.3 图标

- 18 个顶视图图标，24×24 线条 SVG，`currentColor`，自己画（示意稿里就是这一套初稿），放 `components/map/furniture-icons.tsx`，作为 `<symbol>` 注入一次、用 `<use>` 引用。
- 画在家具框里：取短边的 80% 居中；长条家具（宽 > 2.6 倍高）图标靠左、右边写名字。
- 暗色模式用 `ink-soft` / 淡一档的颜色，不另画一套。

### 3.4 数据与端点

| 改动 | 说明 |
| --- | --- |
| `mapRectSchema` 加 `rotation?: 0 \| 90 \| 180 \| 270` | 只管图标朝向；「转 90°」照旧换宽高，再把 rotation +90。不带就是 0，老数据不用动 |
| `storage_locations.icon` 取值收紧 | 家具类型键（10 个）或 null；建 / 改位置时校验，契约加枚举 |
| 迁移 `AddMapDecorations`：`household_maps.decorations jsonb NOT NULL DEFAULT '[]'`、`decorationsVersion int` | 一项 `{ id, kind, roomId, x, y, w, h, rotation }`，最多 200 项 |
| `PUT /map/decorations { version, items }` | 整列替换；版本对不上 409（另一台设备改过，重新拉）；只管理员；进事件域 locations |
| `POST /locations/:id/split`、`POST /locations/:id/merge` | 见 §2.3、§2.4；只管理员；进事件域 locations、inventory、assets |
| `GET /map/export` | 带上 decorations |

装饰类放 jsonb 而不单开表：条目少、没有外键引用、总是整张地图一起读写；整列替换加版本号，撤销 / 重做时整体写回最简单。

## 4. 撤销 / 重做

- 本地维护最近 **50 步**（只在本次编辑内，点「完成」或刷新就清空），每步是一对「做 / 撤」。

| 进撤销栈 | 说明 |
| --- | --- |
| 形状改动（顶点、拖房间连同柜子、柜子挪动 / 缩放 / 转向、矩形化、对齐相邻） | 撤 = 把改之前的形状交给 `useShapeSaver.save()`，照旧写缓存 + 停手 500 ms 保存；连续拖一次只算一步 |
| 装饰类的放置 / 挪动 / 删除 | 撤 = 整列写回上一版 decorations |
| 改名 | 撤 = 改回原名 |
| 新放一个收纳家具 | 撤 = 删掉这个位置（还没记东西时才能删；已经记了东西就提示「里面记了东西，删不了」，这一步从栈里拿掉） |

| **不进**撤销栈，改为操作前确认 | 原因 |
| --- | --- |
| 拆分、合并、从图上拿掉 | 牵涉建 / 归档位置和改记东西，反向操作要再造一堆端点；频率低，确认一下就够（见 §6 待定） |

- 撤销后又做了新操作，重做栈清空（常规做法）。
- 防抖保存与撤销的关系：撤销产生的是一次普通的新改动，和 `useShapeSaver` 的「房间先、柜子后」顺序、失败回滚都兼容；服务端失败回滚时，把栈里对应那一步标成失效（置灰、不能重做）。

## 5. 手机

- 全屏沉浸同样适用：顶部只有「☰ 房间」和「完成」，底部固定工具栏，浮动小工具条规则相同，按钮高 ≥ 44px。
- 手机上能做的（建议放宽，见 §6）：选中、拖 / 拉 / 转柜子和家具、从家具库放家具、改名、删除家具、撤销 / 重做。
- 仍只在电脑上做的：画房间、拖顶点、矩形化、对齐相邻、拆分、合并——「更多」里这几项置灰，点了提示「在电脑上做」。
- 家具库是底部 sheet（半开档，能上滑全屏），sheet 开着时地图上方仍能点选房间（非模态）。

## 6. 需要 King 拍板

1. **手机上的编辑范围**：由「只改名、拖柜子」放宽到「放 / 拖 / 拉 / 转家具、改名、删家具、撤销重做」；房间形状类仍只在电脑上。（建议：放宽）
2. **拆分 / 合并 / 从图上拿掉**：不进撤销栈、改为操作前确认（建议）；还是做成可撤销（约多 1 天，要加「恢复归档」端点和反向合并）？
3. **合并时被并房间里记的东西**：全部改记到目标房间、被并房间归档。（建议：是）
4. **装饰类要不要起名**。（建议：不要，只显示类型）
5. **默认尺寸按 1 单位 ≈ 1 厘米估**，放不下按房间短边 60% 缩。（建议：先这样，看实物再调）

## 7. 工作量估算

按「一笔一个功能提交、CI 绿后合 main」切分；天数是执行 agent 的工作日，含单测、黑盒、e2e（桌面 / 手机 / 不安全上下文冒烟都要过）。

| 笔 | 内容 | 估算 |
| --- | --- | --- |
| 1 · feat(web): 全屏编辑壳 | portal 全屏、进出与自动适配、history 后退、顶 / 底工具栏、房间抽屉、浮动小工具条与「更多」弹层（定位、拖动时隐藏）、原地改名、保存状态 | 1.5 天 |
| 2 · feat(web): 撤销重做与省力改形状 | 50 步栈与 saver 衔接、快捷键；吸附（顶点吸墙 / 直角、柜子吸墙）与参考线；矩形化、对齐相邻；点选顶点删除 | 1.5 天 |
| 3 · feat: 家具库 | 18 个图标；目录与默认尺寸；rotation、icon 枚举契约；decorations 迁移、`PUT /map/decorations`、导出、黑盒；放置 / 四角缩放 / 转向 / 吸墙；看模式渲染（收纳可点、装饰只显示）；手机底部 sheet | 2.5 天 |
| 4 · feat: 拆分与编辑器合并 | 切线求交与两块多边形（shared 纯函数 + 单测）；`split` / `merge` 两个端点（事务、子位置与东西改挂、归档）+ 黑盒；前端交互与确认框 | 1.5 天 |
| 5 · docs / 回填 | 截图（桌面 / 手机 × 亮暗）、进度表、教训、升演示栈 | 0.5 天 |
| **合计** | | **约 7.5 天** |

风险与余量：
- 浮动工具条在捏合缩放中的跟随与翻转最容易反复（预留在笔 1 内）。
- 撤销与「服务端失败回滚」叠在一起的边界要多测。
- 凹多边形被一条线穿过多于两次时直接拒绝，不做通用多边形切割。
