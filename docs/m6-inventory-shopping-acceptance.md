# M6-A1 库存与采购差额验收

## 已交付

- 家庭库存可选择关联菜谱中的食材；自由名称库存和日用品库存继续兼容。
- 同一家庭、同一食材和同一单位只允许一条关联库存，服务端同时校验食材的家庭归属。
- 菜单采购清单按 `菜单需求 - 可用库存 = 建议采购` 重新生成，只有建议数量大于零时才创建自动采购项。
- 自动采购项保存菜单需求、生成时库存和建议采购三项快照，界面直接展示计算明细。
- 采购清单重建继续保留同食材、同单位项目的已勾选状态，并保持事务回滚保护。

## 计算边界

- 只有 `accepted` 或 `cooking` 的菜单菜品参与采购计算，食材数量来自点菜时保存的做法快照；旧菜单没有快照时回退到菜品食材。
- 库存必须同时匹配家庭、`ingredientId` 和单位才可抵扣。同名自由库存、其他单位或其他家庭的库存都不参与。
- 库存足够时不生成采购项；库存为零或没有关联库存时，普通食材按全部需求采购。
- 常备食材已关联库存时按实际余量计算；尚未关联时继续跳过，避免升级后突然产生大量调料采购项。
- 自动采购项记录的是生成时快照。库存变化后需要重新生成清单，已有清单不会被后台静默改写。

## API 与数据

```text
GET   /inventory
POST  /inventory-items
PATCH /inventory-items/:id
POST  /shopping-list/generate
GET   /shopping-list?date=YYYY-MM-DD
```

- `inventory_items.ingredientId` 是可空食材引用。
- `shopping_items.requiredQty`、`availableQty` 和 `totalQty` 分别保存需求、可用库存和建议采购数量。
- 旧库存和手动购物项的新字段均为空，不需要数据回填。

## 自动验收

- 有库存时正确计算差额，库存足够时不生成采购项。
- 单位不同和其他家庭的库存不会错误抵扣。
- 已关联常备食材参与计算，未关联常备食材保持兼容跳过。
- 重建清单保留勾选状态；库存数量变化后使用最新余量。
- 重复食材单位和跨家庭食材关联分别返回 409 与 404。
- 原有数值溢出用例继续验证事务失败后旧清单完整保留。
- Expo Web 回归覆盖用鼠标打开库存编辑器、搜索并选择菜谱食材。

## 后续边界

本批不在勾选采购项时自动增加库存，也不在菜单完成时自动扣减库存。下一批必须先增加不可变库存流水和幂等来源键，再提供用户明确确认的入库、消耗与撤销操作，避免重复点击或接口重试造成数量漂移。
