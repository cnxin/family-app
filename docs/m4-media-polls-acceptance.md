# M4-B 观影片单关联投票验收

> 完成日期：2026-07-30  
> 实施范围：从家庭片单发起通用投票、来源回链、状态同步、并发保护与双视口 Web 交互

## 1. 数据与来源边界

- 继续复用 `polls`、`poll_options` 和 `poll_votes`，不新增观影专用投票表。
- 观影投票通过 `sourceModule=media` 与 `sourceId=household_media.id` 关联真实片单条目。
- 创建时同时校验片单 ID 与当前 `householdId`；其他家庭的来源 ID 返回 `404`。
- 同一片单条目最多有一个未归档且数据库状态为 `open` 的投票。数据库使用部分唯一索引兜底，服务端使用事务级 advisory lock 串行处理并发创建。
- 已过截止时间但尚未持久化关闭状态的旧投票，会在再次发起时先转为 `closed`，再建立新投票。

## 2. 状态协作

```text
发起投票：watchlist -> voting
结束投票：voting -> watchlist
重新开启：watchlist -> voting
删除投票：voting -> watchlist
```

- 只有 `watchlist` 或 `voting` 条目可以发起关联投票。
- 存在进行中的关联投票时，不能绕过投票直接修改观影状态或移出片单。
- 重开投票时重新校验片单仍存在、状态允许且没有另一轮进行中的投票；已排期、观看中、已完成或已放弃的条目不能直接重开。
- 归档历史投票不会覆盖同一片单上较新一轮投票的 `voting` 状态。
- 发起、结束、重开和删除观影投票均写入家庭活动，活动保留片单 ID 与投票 ID。

## 3. 客户端验收

- 片单卡片提供鼠标可点击的投票按钮；没有投票时打开预填表单，已有进行中投票时直接定位到该投票。
- 预填表单固定显示真实片单来源，默认使用“想看 / 这次先不看”，标题、说明、截止时间与候选项仍可调整。
- 投票卡片提供“查看片单条目”回链；创建成功后 URL 聚焦新投票。
- 所有操作均不依赖键盘快捷键，移动和桌面 Web 使用同一业务流程。

## 4. 自动验证

- 全新临时数据库运行 14 次迁移并完成结构漂移检查。
- API 集成测试覆盖来源创建、观影状态同步、顺序与并发重复保护、活动记录和投票期间的片单保护。
- 家庭隔离测试覆盖伪造其他家庭片单 ID 发起投票。
- `corepack pnpm lint`、`corepack pnpm typecheck` 与 API build 通过。
- Playwright 在 390 x 844 与 1440 x 900 视口覆盖片单发起、预填表单、取消与来源回链。
