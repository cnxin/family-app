# M6-A6 外部通知渠道与投递验收

## 已交付

- 站内通知继续作为家庭消息的唯一持久事实；外部服务不可用不会阻止任务、提醒、菜单、观影或访客流程创建站内通知。
- 家庭管理员可建立多个通用 Webhook 或 ntfy 渠道，设置名称、接收地址、可选 Bearer 凭据、启停状态并发送测试消息。
- 渠道地址和凭据使用现有 AES-256-GCM 集成密钥加密保存，AAD 绑定家庭和渠道 ID；API 只返回地址主机与凭据尾号。
- 每位成员独立决定是否使用某个渠道，并按菜单、任务、投票、日历、提醒、观影、访客、积分和系统通知选择接收范围。
- 新站内通知由后台任务幂等路由到已启用的成员偏好；迁移前的历史通知标记为已路由，不会在升级后突然外发。
- 每个“站内通知 + 渠道”只有一个逻辑投递。临时故障使用指数退避自动重试，永久错误进入失败状态，成员或管理员可明确发起新一轮重试。
- 每次请求追加独立尝试记录，保留尝试序号、成功或失败、HTTP 状态、脱敏错误码和时间；删除渠道不删除历史投递快照。
- 通知中心增加站内消息、外部渠道和投递记录三个视图，全部核心操作可用鼠标或触控完成。

## API

```text
GET    /notification-channels
POST   /notification-channels
PATCH  /notification-channels/:id
DELETE /notification-channels/:id
POST   /notification-channels/:id/test
PUT    /notification-channels/:id/preference
GET    /notification-deliveries
POST   /notification-deliveries/:id/retry
```

- `owner/admin` 使用 `manage_integrations` 能力新增、修改、启停、测试和删除家庭渠道；普通成员只能读取已脱敏渠道并维护自己的偏好。
- 普通成员只读取自己的投递记录；管理员可读取本家庭全部成员记录。其他家庭渠道和投递 ID 按不存在处理。
- 渠道名称在家庭内唯一。接收地址只允许完整 HTTP(S) URL，禁止在 URL 中嵌入用户名或密码。
- 渠道测试不创建站内通知或正式投递记录，只更新最近测试状态并写入家庭活动。
- 只有失败投递可以手动重试；渠道已经停用或删除时拒绝重试。

## 数据与迁移

- `notification_channels` 保存渠道种类、加密地址、加密凭据、脱敏提示、启停状态、创建者与最近测试结果。
- `member_notification_preferences` 按成员和渠道唯一保存启用状态与模块列表，默认不启用外部发送。
- `notification_deliveries` 保存逻辑投递、渠道快照、当前状态、总尝试次数、自动重试上限、下次执行时间和最终结果。
- `notification_delivery_attempts` 追加每次实际请求结果，不由重试操作覆盖或删除。
- `notifications.externalRoutedAt` 标记站内通知已经完成外部路由决策；局部索引只扫描尚未路由的数据。
- 迁移 `1785230000000-add-external-notification-delivery` 新增上述结构。当前仓库共 37 个有序迁移，`synchronize` 保持 `false`。

## 投递可靠性

- 路由阶段使用通知行锁与 `SKIP LOCKED`，并依靠通知和渠道唯一约束收敛并发 worker。
- 领取阶段只锁定逻辑投递主表，外部 HTTP 请求不占用数据库事务；响应后再以状态和尝试序号锁定确认结果。
- 外部请求携带稳定的 `Idempotency-Key: <deliveryId>`。Webhook 接收方应按该键去重，投递语义为至少一次而不是不可实现的跨系统恰好一次。
- 默认最多自动尝试四次，间隔按 1、5、25 倍增长并限制在 30 分钟内；`408/409/425/429` 和 `5xx` 可自动重试，其他 `4xx` 进入失败状态等待配置修正和人工重试。
- 请求默认 5 秒超时，不跟随重定向，不读取或记录响应正文。日志只记录错误类别与数据库驱动错误码，不输出地址、请求体或凭据。
- worker 中断的 `processing` 投递在超时后追加中断尝试并重新排队。渠道删除时待处理投递进入配置失败，历史已发送记录保留。

## 外部载荷

- 通用 Webhook 接收 JSON：事件名、稳定投递 ID、站内通知 ID、模块、类型、标题、正文、站内目标路径、创建时间及接收成员 ID/名称。
- ntfy 接收标题和由正文、站内目标路径组成的消息；可选凭据使用标准 `Authorization: Bearer`。
- 载荷不包含家庭账号密码、连接器 Token、访客邀请码、Plex Token 或 MoviePilot API Key。
- 管理员需要自行确认接收服务的隐私政策和网络边界；本系统不会自动安装 NAS 插件或创建公网入口。

## 前端验收

- 通知中心通过可点击分段控件在站内消息、外部渠道和投递记录间切换，深链可直接打开渠道或投递视图。
- 管理员可新增 Webhook/ntfy，替换地址或凭据、清除凭据、启停、测试和二次确认删除；完整地址与凭据不会回显。
- 每位成员可通过开关启停自己的渠道偏好，通过复选按钮选择通知模块，至少保留一个模块。
- 渠道卡显示类型、主机提示、启停、最近测试成功或失败；测试、编辑、启停和删除均有加载、成功与失败反馈。
- 投递记录显示等待、处理中、等待重试、成功和失败状态，以及最近三次尝试、下次重试时间、脱敏错误和明确重试按钮。
- 布局使用稳定尺寸、换行按钮和响应式宽度，移动 Web 与桌面 Web 不依赖键盘快捷键。

## 自动验收

- 全新数据库初始化、旧结构升级、重复 seed 和实体结构漂移覆盖四张新表、外部路由字段、约束、外键与局部索引。
- 回归启动随机本地 HTTP 接收器，验证 Webhook 与 ntfy、Bearer 凭据、测试消息和响应脱敏，不访问真实 NAS 或互联网服务。
- 普通成员管理渠道返回 403，随机渠道 ID 返回 404；管理员可查看家庭历史，成员只读取本人投递。
- 临时 `503` 连续失败验证三次尝试后成功、尝试历史完整且所有请求复用同一幂等键。
- 永久 `400` 验证停止自动重试；服务恢复后成员手动重试成功，并保留原失败尝试。
- 回归验证重复 worker 扫描不重复建投递、成员停用偏好与模块过滤不外发、删除渠道后历史快照仍可读取。
- 渠道创建、更新、测试、删除和人工重试进入家庭活动审计。
- 完整 API 回归继续覆盖家庭隔离、登录限流、日志脱敏、库存、资产、积分、提醒、访客和媒体连接器。

## 部署边界

- 调度间隔、请求超时和重试基准可分别通过 `NOTIFICATION_DELIVERY_POLL_INTERVAL_MS`、`NOTIFICATION_DELIVERY_TIMEOUT_MS`、`NOTIFICATION_DELIVERY_RETRY_BASE_MS` 调整。
- 渠道加密复用 `INTEGRATION_SECRET_KEY`；生产部署必须使用稳定的 32 字节主密钥并独立备份密钥，数据库备份本身不能替代密钥备份。
- 当前不直接实现 APNs/FCM、SMTP、短信或特定消息平台 SDK。此批提供可自托管的 ntfy 与通用 Webhook；新增专用提供方时继续复用同一偏好、逻辑投递和尝试历史契约。
